# Build audience app

Read the brief, method, example and brand notes under `../../second-brain/`. Use `../../app-source/` as the complete reference implementation when present. The app should help an attendee follow the talk and leave with a useful artifact in minutes.

Make the working learning board the primary destination. Follow `../build-learning-board/SKILL.md`. Attendees can explore six guided stops, make a decision, read explanatory feedback, rehearse and download an action note. Offer the same learning content in a readable panel for keyboard and phone users. Keep the actual brain files and build skill one click away. Provide three clear destinations: the board, the brain and the GitHub kit. Supply a ready-built static folder with simple download and launch instructions.

Preserve the optional recipe builder and pilot planner when adapting this app. Their source preview must identify fictional sources and label deterministic behaviour honestly. Personal work stays on the device unless the user requests shared storage. State whether each feature survives a reload. Export must work even if persistence or clipboard access is blocked.

Use the approved visual tokens and assets. Support phone, desktop, touch, keyboard, reduced motion and useful print output. Maintain the application architecture and package lock. Preserve existing participant work on reload, validate imported/restored data, handle corrupt storage and confirm before clearing work. Include the manual and download links. Test actual interactions and generated files, not just screenshots. Use the check-session skill before delivery.
